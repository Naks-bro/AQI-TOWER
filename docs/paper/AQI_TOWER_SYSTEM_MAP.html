AQI Tower System Map

AQI Tower is a tower-type air purifier that we have designed entirely in software so far. CAD models, airflow simulations, a 3D web viewer and analysis scripts all live in one Git repository. This page explains how that repository splits into four layers, what each layer depends on and which tools it uses, so every member can find their part and see how it connects to the rest.

Physical prototypes built: 0 Airflow CFD: done (simulated) 3D web viewer: done Measurement tools: ready, no data yet First build (D01): CAD for review only

Every performance number on this page comes from simulation or calculation. None of it has been measured on hardware. When presenting, say "the model predicts", not "the tower delivers".

What we are building

Project specifications

There are two designs. The full tower is the research concept that all the CFD was run on. D01 is a smaller indoor demonstrator picked as the first thing to actually build, because the full tower needs a heavy mains fan, sheet-metal work and rated wiring that nobody has reviewed yet.

The architecture

Four layers, one per member

Data flows upward: geometry feeds the simulation, simulation results feed the viewer and the calculators, and the calculators feed design decisions. Layers only exchange files (JSON, OpenFOAM dictionaries, CSV), so each member can rerun their layer without breaking anyone else's. Owners are placeholders; assign one member to each.

Layer 4

Data, analysis and decisions

Owner: [Member 4]

Turns numbers into decisions, and will take in real measurements once D01 exists. It answers questions like "how much airflow is left if we add this filter?" and "did the room clean up faster with the purifier on?"

Main files

  • scripts/analysis/build_screening.py, fan_duty_screen.py, d01_pressure.py: operating points and pressure budgets
  • scripts/monitoring/record_measurements.py: imports sensor readings (JSONL) into a checked CSV
  • scripts/analysis/indoor_decay.py: CADR = V × (k_on − k_off)
  • scripts/reports/*.py: build the PDF packages
  • docs/PHASE18_*, docs/PHASE19_*: decision matrices

Takes in → gives out

  • In: CFD results JSON, fan curves in data/fans/, filter data, future sensor logs
  • Out: results/*.json, checked CSV, CADR estimate, PDF reports

Layer 3

Visualization (web viewer)

Owner: [Member 3]

Shows the tower and the simulation results in a browser, so the guide, examiners and teammates can see the airflow without installing CFD software. This is the part that looks most like a digital twin.

  • threejs/data/: towerConfig.js, cases.js, engineeringStatus.js
  • threejs/tools/cfd/export_scalar_planes.py: pvpython export

Layer 2

Simulation (CFD)

Owner: [Member 2]

Predicts how air moves through the tower: how much flows, where it swirls back, how much pressure each filter costs and where particles end up. This is where the design mistakes were caught, including the 38–48% of air leaking around the HEPA filter.

Main files

  • scripts/simulation/prepare_*.py: write blockMeshDict and the fan boundary condition from JSON
  • scripts/simulation/run_*.sh: run OpenFOAM in WSL
  • scripts/simulation/analyze_*.py: extract flow, Δp and bypass
  • scripts/simulation/phase12b_particle_tracking.py: 224 particles, 4 sizes
  • cfd/: cases V00, V01_fan, GEO_A/B/C, FILTER_H13/CASE_M_SEALED

Takes in → gives out

  • In: tower geometry, fan curve data/fans/systemair_KVO_250.json, HEPA rated point (300 Pa at 2.84 m/s)
  • Out: flow fields, plus JSON and Markdown summaries in results/

Read first

Owner: [Member 1]

How we got here

Phase history

  1. Phases 1–5: environment setup, concept, first CAD (V00) and first CFD with a placeholder fan.
  2. Phases 6–7: real fan chosen (KVO 250) and coupled to the CFD through its catalogue curve.
  3. Phase 8: three geometry variants; GEO_C cut modelled pressure loss from 17.3 to 3.5 Pa.
  4. Phases 9–10: HEPA filter added, 38–48% bypass found and sealed, 1,332 m³/h predicted.
  5. Phases 11–12: HEPA evidence audit, CADR method, particle tracking (about 62% reach the filter).
  6. Phases 13–17: carbon stage research, formaldehyde chosen as target gas, bench test rig and procurement plan. No hardware bought.
  7. Phases 18–19: water spray rejected, G4 pre-filter specified.
  8. October 2026: build planning: packaging CAD, electrical plan, measurement tools and the D01 indoor demonstrator.
