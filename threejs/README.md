# AQI Tower — Engineering Viewer T3

Interactive browser-based 3D engineering viewer for the AQI Tower GEO_C concept.
T3 adds real CFD scalar field visualization — velocity magnitude and static pressure sampled on 2-D planes from existing solved OpenFOAM cases.

**PARALLEL VISUALISATION TRACK.** This viewer is an engineering representation only. CFD field planes are post-processed from existing solved fields; they are NOT raw CFD data and are NOT physically validated. All quantities are labeled SIMULATION ONLY.

## Technology

Vite + Three.js + JavaScript ES modules. No React, no TypeScript.

## Quick start

```bash
cd threejs
npm install
npm run dev       # dev server at http://localhost:5173
npm run build     # production build → dist/
```

|---|---|---|

In CFD FIELD mode, the explode slider is disabled — spatial CFD planes cannot be offset from their original coordinates without becoming physically misleading.

## T3 — CFD scalar field visualization

### CFD field audit

| Case | Path | Final timestep | Status | Cells | U range | p range (Pa) |
|---|---|---|---|---|---|---|
| GEO_C | cfd/GEO_C | 926 | CONVERGED | 63,780 | 0.001–5.620 m/s | −20.43–−0.06 Pa |
| GEO_C_CONFIRM | cfd/GEO_C_CONFIRM | 926 | CONVERGED | 63,780 | 0.001–5.620 m/s | −20.43–−0.06 Pa |
| CASE_M_SEALED | cfd/FILTER_H13/CASE_M_SEALED | 5000 | PARTIALLY CONVERGED | 67,838 | 0.001–5.268 m/s | −128.92–−0.17 Pa |

GEO_C and GEO_C_CONFIRM have identical fields — confirmed deterministic reproducibility. CASE_M_SEALED has a much larger pressure range due to the H13 filter resistance (ΔP ≈ 111 Pa).

### Pressure unit interpretation

OpenFOAM `p` field has dimensions `[0 2 -2 0 0 0 0]` = m²/s² = **kinematic pressure** (p/ρ, used by incompressible RANS solvers). All values in solver units are negative (gauge relative to outlet reference).

Conversion: **P_static (Pa) = p_kinematic × ρ** where ρ = 1.20 kg/m³ (from `constant/physicalProperties`).

The export script applies this conversion and marks the field as `DERIVED FROM CFD PRESSURE FIELD`. Values are gauge pressure relative to the solver reference. Do not interpret absolute values as total pressure.

### Planes exported

| Plane ID | Normal | Position | Domain covered |
|---|---|---|---|
| `longitudinal` | y | y = 0.400 m | Full flow path from inlet to riser top |
| `filter_xsec` | x | x = 0.305 m ± 20 mm slab | Filter face / STAGE_03 cross-section |

The longitudinal plane at y = 0.400 m is the exact center of the flow domain (domain depth y ∈ [0.10, 0.70] m). This is the same plane used in the existing phase10b_visualize.py. The cross-section at x = 0.305 m corresponds to STAGE_03_mid in GEO_C metrics and the actual filter baffle position in CASE_M_SEALED.

### Export pipeline

**Dependency:** ParaView pvpython (installed in WSL)

**Tool:** Uses `OpenFOAMReader` + `vtkCellCenters` + `scipy.interpolate.griddata` (same pattern as existing `scripts/simulation/phase10b_visualize.py`).

**Grid resolution:**
- Longitudinal: 100 × 130 ≈ 13,000 grid points per field (domain: x∈[0, 0.71] m, z∈[0.14, 1.86] m)
- Filter cross-section: 65 × 75 ≈ 4,875 grid points (domain: y∈[0.09, 0.71] m, z∈[0.14, 0.88] m)

**Run from AQI-TOWER root (WSL):**
```bash
pvpython --force-offscreen-rendering threejs/tools/cfd/export_scalar_planes.py
```

**Output:** 12 JSON files + `cfd_index.json` in `threejs/public/data/cfd/`. Total size ≈ 650 KB.

### JSON format

Each export file contains:
```json
{
  "schema_version": 1,
  "case_id":        "GEO_C",
  "case_path":      "cfd/GEO_C",
  "source_timestep": "926",
  "field":          "U_MAGNITUDE",
  "field_description": "Velocity magnitude |U|",
  "derivation":     "DERIVED FROM CFD VELOCITY FIELD: |U| = sqrt(Ux² + Uy² + Uz²)",
  "units":          "m/s",
  "plane":          "longitudinal",
  "grid":           { "type": "longitudinal", "n_axis1": 100, "n_axis2": 130, ... },
  "data_min":       0.016,
  "data_max":       5.211,
  "n_valid":        10102,
  "n_total":        13000,
  "values":         [...],   // null where outside domain
  "convergence_status":  "CONVERGED",
  "validation_status":   "SIMULATION ONLY — NOT PHYSICALLY VALIDATED",
  "provenance":     { ... }
}
```

### Colormap

Six-stop turbo approximation: dark purple → cyan → green → yellow → orange → dark red. Perceptually suitable for CFD scalar visualization. Higher value = higher scalar only — no danger interpretation.

### Browser visualization limitations

- Cells are sampled on a grid; outside-domain cells are blank (null)
- Visual interpolation between grid points is for rendering only — not additional CFD resolution
- The planes are 2-D slices; no 3-D volume rendering
- Interpolation from scattered cell centers uses `scipy.griddata` linear method
- No streamline rendering (streamlines not exported; would require separate pipeline)

## Particle trajectory data

Phase 12B (`scripts/simulation/phase12b_particle_tracking.py`) does **not** store path coordinates — only terminal positions are tracked in-memory and discarded after the run. Only summary statistics exist on disk in `results/PARTICLE_CFD/particle_arrival_fractions.json`.

**Viewer behaviour:**
- On startup, the viewer attempts `fetch('./data/particleTrajectories.json')`
- If found: **REAL TRAJECTORY DATA LOADED** — actual coordinates from the export tool
- If not found: **SCHEMATIC MODE** — exact seed grid positions from script parameters; terminal positions geometry-derived using seeded PRNG (reproducible)

**Generating real trajectories:**

```bash
# WSL/Linux with ParaView pvpython
pvpython --force-offscreen-rendering threejs/tools/export_particle_trajectories.py
# Output: threejs/public/data/particleTrajectories.json (~2–3 MB)
```

The export tool replicates Phase 12B integration (equilibrium-slip Euler, dt=0.004 s, frozen CASE_M_SEALED field) and stores path waypoints every 25 steps (≈0.1 s intervals, max 60 points per particle).

**Trajectory JSON format:**
```json
{
  "meta": { "version": 1, "n_seeds": 224, "n_sizes": 4, "store_interval_steps": 25 },
  "sizes": {
    "0p3um": {
      "d_m": 3e-7,
      "particles": [
        { "outcome": "FILTER_ARRIVAL", "path": [[x0,y0,z0], [x1,y1,z1], ...] }
      ]
    }
  }
}
```
Coordinates are in Three.js space (x=flow−0.350, y=CAD_z−0.925, z=CAD_y−0.400).

## Known limitations

- Phase 12B trajectories not exported; viewer shows schematic paths until pvpython export is run
- No real CFD streamlines exist; ARCHITECTURE mode airflow is schematic topology only
- GEO_C RANS cases did not fully converge; all CFD quantities are screening-level estimates
- No turbulent dispersion in Phase 12B particle model (equilibrium-slip Euler only)
- η(d_p) filter capture efficiency is not available — only arrival fractions are displayed
